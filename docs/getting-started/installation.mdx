Toolgrain's six libraries are published on npm. Install matching stable versions
across Toolgrain packages. The commands below resolve npm's `latest` tag. See the
[package changelogs](/project/changelog) for release notes.

## Requirements

Use Node.js **24.20.0 or later within 24.x**, or Bun **1.4.4 or later within 1.x**
for your application. TypeScript requires **5.5.4 or later with strict mode**;
Zod requires **`^4.6.6`**. Both Classic and Mini user schemas are accepted.
See the [support policy](/project/support-policy) for the complete contract.

## Install packages

For a stdio server or standalone Node HTTP listener:

```bash
mkdir hello-toolgrain
cd hello-toolgrain
npm init -y
npm pkg set type=module
npm install @toolgrain/mcp @toolgrain/node zod@^4.6.6
npm install --save-dev typescript @types/node@^24.10.0
```

For an existing Web Request/Response application, add `@toolgrain/http`.
Add `@toolgrain/jwt` or `@toolgrain/clerk` when protecting HTTP
endpoints. Frameworks keep ownership of their listener and application lifecycle.

## Configure TypeScript

Toolgrain exports compiled ESM and declarations. CommonJS and Node's `node10`
resolution mode are unsupported. For the modular tutorials, save this configuration:

```json tsconfig.json
{
  "compilerOptions": {
    "target": "ES2023",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "types": ["node"],
    "strict": true,
    "outDir": "dist",
    "rootDir": "src",
    "skipLibCheck": false
  },
  "include": ["src/**/*.ts"]
}
```

Use `.js` extensions for relative imports in TypeScript intended for Node. Compile
with `tsc`, then run the emitted entry point. Frameworks may own compilation and
use their own supported module resolution.

`@toolgrain/mcp` includes JavaScript/declaration maps and TypeScript sources for
debugging and editor navigation. Public exports still resolve to compiled `dist`
files.

## Develop Toolgrain itself

You do not need to clone this repository to use the libraries. Repository
contributors use the pinned **Bun 1.3.14** package manager, independently of the
supported Bun application runtime. See [development](/project/development).

Continue with the [quickstart](/quickstart) for one file, or
[your first tool](/getting-started/stdio) for a modular application.
