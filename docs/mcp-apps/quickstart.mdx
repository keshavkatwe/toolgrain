The runnable example contains weather and sales widgets, plus one shared HTML entry. It uses deterministic demo data and needs no API credentials.

## Build the workspace example

Use Bun 1.3.14 for repository tooling and a supported Node 24 runtime:

```sh
bun install --frozen-lockfile
bun run build --filter=@toolgrain/react-apps-example
```

Run the application with Bun 1.4.4 or later:

```sh
bun run --cwd apps/react-apps-example start
```

The HTTP endpoint is `http://localhost:3008/mcp`. The example also has `start:stdio` for a host connecting to a local process. Opening the HTML in a browser alone does not create an Apps connection.

## Create browser bindings

Keep the exported tool map in a module your frontend can import by type:

```tsx
import type { tools } from "../server/tools";
import { createApp } from "@toolgrain/react";

const { AppProvider, useToolResult, useToolCall } = createApp<typeof tools>();

function Weather() {
  const initial = useToolResult("weather");
  const refresh = useToolCall("weather");
  const result = refresh.result ?? initial.result;
  if (initial.error) return <p role="alert">{initial.error.message}</p>;
  if (!result) return <p>Loading…</p>;
  return <button disabled={refresh.pending}
    onClick={() => void refresh.call({ city: "London" }).catch(() => {})}>
    {result.structuredContent?.temperature}°C
  </button>;
}

export function App() {
  return <AppProvider appInfo={{ name: "Weather", version: "1.0.0" }} tool="weather">
    <Weather />
  </AppProvider>;
}
```

The example's full components display call errors as well. Type imports do not bundle server handlers or credentials. Build this React entry into HTML and [register that HTML as a resource](/mcp-apps/server).

See the [example source](https://github.com/keshavkatwe/toolgrain/tree/main/apps/react-apps-example), [build recipe](/mcp-apps/build), and [client acceptance procedure](/mcp-apps/compatibility).
